|                  写给 CPU 工程师的 Git 肌肉记忆手册                  |
+======================================================================+

作为底层硬件工程师，我们不需要懂 Git 的 100 种花式用法，
只需要把下面这 4 套连招刻进肌肉记忆，就足以应对 99% 的协同开发！

►【第一套：开工与下班的常规连招】◄
这套连招每天必须打一次，保证你的代码永远是最新的。

[每天早晨开工]
$ git checkout main          --> 回到安全的主线基地
$ git pull origin main       --> 把队友昨晚的牛逼代码拉下来同步
$ git checkout -b feature-x  --> 切出一个叫 feature-x 的新分支开始干活

[每天晚上下班]
$ git add .                  --> 把今天所有的修改装进箱子
$ git commit -m "说明"       --> 给箱子贴上封条并写上说明（千万别乱写）
$ git push origin feature-x  --> 把箱子扔给云端服务器

------------------------------------------------------------------------

►【第二套：时空穿梭（分支管理）】◄
分支就是平行宇宙，我们在平行宇宙里搞破坏不会影响主宇宙。

$ git branch                 --> 查看当前有哪些宇宙（带 * 的是你当前所在的）
$ git checkout <分支名>      --> 穿越到另一个宇宙
$ git branch -d <分支名>     --> 毁灭一个旧宇宙（合并完代码后必须做！）
$ git branch -D <分支名>     --> 暴力毁灭（如果 Git 拦着不让你删，用大写 D）

------------------------------------------------------------------------

►【第三套：后悔药与急救箱】◄
如果你把代码写炸了，或者 Vivado 又拉屎了，用这套指令保命。

$ git status                 --> 查看当前状态（变红的就是你修改或新增的垃圾）
$ git diff                   --> 看看你具体改了代码的哪一行（按 Q 退出）

[撤销操作]
$ git restore <文件名>       --> 放弃对某个文件的修改，让它恢复到昨天的样子
$ git restore .              --> 极其危险：放弃当前所有未提交的修改！慎用！

[版本回退]
$ git log                    --> 查看历史提交记录（能看到每次的 Hash 码，按 Q 退出）
$ git reset --hard HEAD^     --> 让整个工程乘坐时光机回到上一次 commit 的状态

------------------------------------------------------------------------

►【第四套：协同冲突解决（进阶）】◄
如果你在 pull 队友代码时，Git 报了 "CONFLICT (合并冲突)"：

1. 不要慌，打开报错的文件。
2. 你会看到文件里出现了 <<<<<<< HEAD 和 ======= 这样的外星文字。
3. 等号上面是你写的，等号下面是队友写的。
4. 删掉外星文字，把你和队友的代码手动改成最终想要的样子。
5. 重新执行 git add . 和 git commit -m "fix conflict"，冲突就搞定了！

+►【第五套：报错急救（Push被无情拒绝）】◄
当你敲下 git push，但屏幕爆出一大堆红字，并带有：
"rejected" 和 "remote contains work that you do not have locally" 时：

原因：你的队友刚刚向云端提交了代码，云端比你本地的版本还要新！Git 为了防止你覆盖队友的心血，锁死了你的推送权限。

[急救三步曲]：
1. 先把自己的代码打包存好：
   $ git add .
   $ git commit -m "保存本地修改准备融合"

2. 把云端的新代码拉下来融合：
   $ git pull origin main
   (注：如果弹出奇怪的编辑器窗口，直接输入 :wq 按回车即可)

3. 融合成功后，重新冲锋：
   $ git push origin <你的分支名>
